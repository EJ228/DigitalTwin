# DigitalTwin.ai

**Accenture Innovation Challenge 2026 — Round 2, Track 4**
Team ACE · Indian Institute of Technology Guwahati
Aditya Garg · Charvit Rajani · Eklavya Jain

A live digital twin of a mixed-model vehicle assembly line that finds the
bottleneck while it is still moving, and catches a fixture drifting before the
defect exists — both from the one signal every station emits: the timestamp of
a part entering and leaving.

## Headline results

| | Baseline | This twin |
|---|---|---|
| **Escape window** — vehicles built before the drift is flagged | 83 (end-of-line inspection) | **23** |
| **Bottleneck disruptions found** | 48% (utilisation report) | **95%** |
| **Hold-phase hit rate** | 0.20 | **0.61** |

A **72% reduction in the escape window**, at a fixed budget of one false alarm
per 1,200 parts. Measured over 4 evaluation seeds × 10 injected disruptions,
with thresholds calibrated on separate drift-free runs.

Every figure in this README is regenerated by `run_all.py` into
`results/RESULTS.md`. If they disagree, the generated file is right.

## Quickstart

**The numbers** — forty seconds, no Node required:

```bash
pip install -r requirements.txt
python run_all.py
```

Generates every dataset, runs the invariant suite and the anti-circularity
audit, evaluates both engines, and writes `results/RESULTS.md`.

**The dashboard** — backend plus frontend:

```bash
make dev            # starts FastAPI on :8000 and Vite on :5173
```

Then open <http://localhost:5173>. Requires Node 18+. Or run them separately
with `make api` and `make web`.

```bash
python run_all.py --quick     # 2 seeds
make verify                   # invariants + audit only
make flow                     # bottleneck evaluation, verbose
make quality                  # escape-window evaluation, verbose
pytest -q                     # test suite
```

No data ships with this repo. Everything regenerates from seeds, so a reviewer
reproduces our exact numbers rather than trusting a committed CSV.

## The dashboard

Four views over one twin, all fed by the same event log.

| View | Question it answers |
|---|---|
| **Floor supervisor** | What do I do in the next thirty seconds? Live station ribbon, andon banner, drift chart climbing to its threshold. |
| **Escape window** | The split screen. One fault, two worlds: cars built before end-of-line inspection notices, against cars built before the twin does. |
| **Shift log** | Where the constraint was, hour by hour. Disruption log with detection lag. Detection rate against conventional methods. |
| **Rollout case** | Cars saved, annualised value, sensor coverage, and which stations to instrument next. |
| **Model audit** | The four offline engines: hazard model with its leak check and SHAP attribution, blind-station skill and EIG ranking, Little's Law coherence, conformal guarantee. |

Two demo controls in the header:

- **Replay** — pause, scrub, and 0.5× to 10× speed. Controls are sent over the
  open websocket rather than reconnecting, so nothing flickers.
- **Turn off S08 sensors** — simulates the drift station as a legacy manual bay.
  The drift chart stops claiming to know things and says what it cannot see;
  bottleneck detection carries on unaffected, because it only ever needed
  timestamps.

## Scope — implemented vs designed

Round 1 proposed nine engines. With three days for Round 2 we built the spine
properly instead of stubbing all nine.

**All nine engines from the Round 1 deck are built and measured.**

| # | Engine | Status |
|---|---|---|
| 1 | LSTM buffer forecaster | **Built** — beats persistence at 4/4 horizons |
| 2 | Active-period bottleneck | **Built** |
| 3 | Little's Law check | **Built** — 9.0% WIP error |
| 4 | CUSUM / EWMA multivariate | **Built** — six charts |
| 5 | GraphSAGE | **Built** — AUC 0.941 vs 0.910 without aggregation |
| 6 | Survival / hazard model | **Built** — MCC 0.561 |
| 7 | Virtual metrology | **Built** — skill positive at 20/35 |
| 8 | Gaussian-process posterior | **Built** |
| 9 | Expected Information Gain | **Built** — real EIG in bits |

Plus, beyond the nine: **inventory-augmented bottleneck walk** (the reason
detection went from 72% to 95%), **conformal alert calibration**, **Monte Carlo
MPC counterfactual**, **live replay backend**, and a **five-view dashboard**.

Both neural engines are written by hand in NumPy — backpropagation through time
for the LSTM, the mean aggregator for GraphSAGE — with gradient checks against
finite differences in the test suite. No deep-learning framework, so the project
installs in seconds, runs anywhere, and can be read end to end by a reviewer
checking there is no leakage hiding in a library call.

**Still roadmap:** LLM copilot, Bosch validation.

Naming which is which is the honest version. Nine half-built engines is the
other one.

## Why a simulator is the primary substrate, not a fallback

The headline claim is a **counterfactual**: N vehicles escaped without the twin,
M with it. That requires running the same line twice under identical conditions.
History happens once, so no archived dataset can supply it.

The same is true of every other metric. "Which station was the momentary
bottleneck at 14:32" is a derived quantity no MES records. ARL₁ needs the exact
instant drift began, knowable only if you injected it.

The simulator is a measurement instrument, not a stand-in for data we could not
get. A wind tunnel is not a weaker aeroplane.

Bosch Production Line Performance stays in the plan as a **reality check for the
quality model only** — 1.18M real parts, sub-1% defect rate, genuinely filthy
features. It cannot validate flow: no buffers, no blocking, no takt, and
6-minute timestamp granularity against our 60-second takt. We say so rather than
let a reviewer find it.

### Guarding against circularity

1. **Structural.** Truth tables are read by exactly one module, `scoring.py`.
   `dtwin/audit.py` walks the prediction modules and fails the build if any of
   them so much as mentions one. It also walks `web/src` and fails the build if
   a display component presents a typed-in number as a measurement — see below.
2. **Calibrated, not chosen.** Defect-physics constants are solved numerically
   against a Bosch-anchored target rate — see
   `scripts/calibrate_defect_physics.py`. Every other parameter is listed in
   `docs/ASSUMPTIONS.md` with its rationale.
3. **Asserted hard.** `scripts/test_invariants.py` fails the build if the drift
   ever becomes visible to a univariate chart.

### Seed protocol

| Seeds | Purpose | Drift |
|---|---|---|
| 7, 21, 22, 23 | Evaluation — every reported number | on |
| 11, 12 | SPC threshold calibration only | off |
| 31, 32 | Detector hyperparameter tuning only | on |

No seed is used for two purposes.

## The line

35 stations — 12 body, 10 paint, 13 final assembly. 60-second takt. Service
times are **derived** from a balanced target load, not hard-coded:

```
mean_service = target_load × (1 + offset) × availability / mix_multiplier
```

Every station sits within ±2% of target. This matters: a line with one obviously
slowest station makes bottleneck detection trivial and resembles no real plant.
Ours is balanced to 3.5% spread, so the baseline constraint leads its runner-up
by **0.05 seconds**. The identity of the bottleneck is genuinely marginal, and
small perturbations decide it.

Sensor coverage: 22 rich (OPC-UA, every part), 7 sparse (2 tags, every 3rd–5th
part), 6 blind (manual and legacy bays, timestamps only). **37%
under-instrumented**, matching the Round 1 envelope and the brief's "majority
well-instrumented, meaningful minority reliant on manual checks."

Modelled: part flow, finite buffers, blocking, starving, stochastic service
times, mixed-model variants, breakdown and repair, imperfect end-of-line
inspection, off-line rework, correlated process tags.

Skipped: CAD geometry, robot kinematics, weld-point physics, thermal and
structural simulation, supply chain. **Fidelity is a cost.** We spend it only
where it changes a decision inside one shift.

# The flow engine

## Reconstructing station state from timestamps alone

`dtwin/reconstruct.py` makes the "one signal every station emits" claim literal.
From ENTER/EXIT timestamps plus buffer capacities (engineering design data, not
sensor data):

- **Buffer level** is *exactly* recoverable — the parts that left station k but
  have not yet entered k+1.
- **Blocking** is identified by whether a cycle ended against a full downstream
  buffer, and its duration estimated by subtracting the median *unblocked* cycle
  time for that station and variant. Using unblocked cycles as the reference is
  what keeps it from being circular.

Measured against the simulator's true state timeline, the inferred active
fraction is accurate to **about 1 percentage point per station**. No process
sensors involved, so this holds identically at the six blind manual bays.

## Results — 4 seeds × 10 disruptions

| Detector | Disruptions found | Hold-phase hit rate | sd across seeds |
|---|---|---|---|
| **Bottleneck walk** (active period + inventory) | **95%** | **0.61** | 0.042 |
| Active period alone | 72% | 0.38 | 0.030 |
| Utilisation report (30 min) | 48% | 0.20 | 0.063 |
| Longest queue | 22% | 0.11 | 0.019 |

## Two failures that changed the design

**The first scenario was ill-posed.** At 92.5% utilisation every station ran
near-continuously, so for much of the run there was no bottleneck to find, and
random breakdowns with MTTR in the hundreds of seconds swamped every injected
episode. We dropped to 83% planned utilisation and scaled availability to
~99.6%. Now quiet periods are honestly ambiguous and disruptions create a real
constraint.

**The first ground truth was wrong.** We defined the true bottleneck as the
station with the highest theoretical load from configuration. Investigating a
"failure" showed the detector naming a station that was genuinely 100% active,
while the truth named one that had not started degrading yet. Config-derived
load ignores transient WIP. We now score against the **injected episodes** —
defensible, and the actual business question: when a station starts binding, do
you name it, and how fast?

## Why active period alone was not enough

Active fraction ties. An assembly line carries tens of buffer slots between body
and final assembly, so when a final-assembly station starts binding the
disruption takes *hours* to propagate upstream. Body stations keep running 100%
active and tie with the true constraint. That tie is real physics; no amount of
active-time bookkeeping resolves it.

Inventory resolves it. The constraint has a **full buffer behind it and an empty
buffer in front**, and that gradient appears immediately. This is Roser,
Lorentzen & Deuse (2015), already cited in the Round 1 deck. Adding it took
detection from 70% to 100%.

Hyperparameters (window 1800 s, weight 0.6) were grid-searched on **held-out
seeds**, never on a reported one. The surface is nearly flat — weight from 0.3
to 1.5 moves the score under 0.01 — so the result does not live on a tuned
constant.

**Known weak spots.** Two of ten episodes score poorly: the first station after
the paint zone-exit bank, and the end-of-line station itself. Both sit next to
the largest buffers on the line, consistent with the propagation-delay
explanation above. Reported rather than tuned away.

# The quality engine

## The scenario had to get harder, twice

Our first drift was a 0.6σ mean shift on two correlated gaps. Measured against a
proper univariate CUSUM, it was caught in 26 parts — barely better than
end-of-line. **A mean shift, however small, is eventually visible to a
univariate chart.** The deck's claim that "a drift within spec on every tag
alarms on none" is true only of *spec-limit* alarms, not of univariate SPC.

So we changed the physics. The fixture now develops **play**: the two locating
pins stop moving together. Correlation collapses from r = +0.86 to r = −0.15,
and *every marginal distribution is untouched* — the worst tag mean moves 0.03σ,
spreads change under 9%, spec breaches stay at 0.15%. The panel is mis-set when
the gaps diverge, so defects rise from 0.7% to 12.9%.

No univariate method can detect this at any threshold or run length, because no
single tag's distribution has changed. It exists only in the relationship
between tags. That is asserted in the invariant suite, not claimed.

MCUSUM and MEWMA detect shifts in the **mean vector**. With no mean shift, the
deviations stay centred on zero and a mean-targeting accumulator cancels itself
out. MCUSUM needs 132 parts on average — worse than end-of-line.

What changes is multivariate **dispersion**: observations sit further from the
in-control centre because the covariance they are measured against no longer
describes them. `T2CUSUM` accumulates standardised Hotelling T² above its
in-control expectation, giving the memory that single-point T² lacks.

## Escape window — all methods at one alert budget

Budget: **one false alarm per 1,200 parts** (20 hours at 60 units/h). Thresholds
bisected to hit that budget on drift-free runs, never on a reported run. Phase I
reference from the first 400 parts; no detector is told when drift starts.

| Detector | Runs detected | Mean escape | Median | Worst |
|---|---|---|---|---|
| **End-of-line inspection** | 4/4 | **83.2** | 84.0 | 89.0 |
| Spec-limit alarm | 2/4 | 288.5 | 288.5 | 332.0 |
| Univariate CUSUM (per tag) | 1/4 | 30.0 | 30.0 | 30.0 |
| MCUSUM (mean-based) | 0/4 | n/a | n/a | n/a |
| Hotelling T² (no memory) | 4/4 | 20.8 | 18.5 | 39.0 |
| MEWMA | 4/4 | 29.0 | 32.0 | 51.0 |
| **T²-CUSUM (ours)** | 4/4 | **23.0** | 24.5 | 34.0 |

**83 vehicles → 23. A 72% reduction, at a fixed alert budget.**

Three of the deck's assertions are now measurements: the spec-limit alarm misses
the fault outright in half of all runs; univariate accumulation is an order of
magnitude too slow; and the escape window is dominated by the ~70 units of WIP
between S08 and end-of-line inspection, not by inspection accuracy.


## Hazard model — defect risk at station k from stations 1..k only

Trained on run_s21, run_s22, run_s23, tested on the held-out run_s7.
64 features, every one of them upstream: downstream columns are
**dropped before training**, not masked at inference. A model that can see
downstream learns to *explain* a defect after the fact — the failing torque check
at station 31 predicts the failure at station 31 — which scores beautifully and
is operationally worthless. Blinding it forces prediction.

It trains on **end-of-line inspection outcomes**, the only label a real plant
has. Not on which station caused the defect: that exists in our simulator and
never would on a real line.

| Metric | Value |
|---|---|
| **MCC** | **0.561** |
| ROC AUC | 0.839 |
| Average precision | 0.556 at a 5.2% base rate |
| Predict-all-good | 94.8% accurate, **MCC 0.000** |
| Downstream leak check | clean, asserted in code |

That baseline row is why accuracy is not a headline anywhere in this project.
Attribution is SHAP, and the top feature is `s08_gap_diff_abs` — the model
independently found the gap *difference*, which is exactly the physical
squareness error the fault mechanism acts on.

One earlier failure worth recording: a chronological split *inside* one run
scored at chance. One run holds one drift event, so the train half contained no
positives at all and the model never saw a drift while training. Pooling runs and
holding one out is both the fix and the better experiment.

## Blind-station engine — virtual metrology, GP posterior, EIG

Three engines, one pipeline. Every station is inferred from its neighbours with
its own readings withheld — **including stations we can see**, which is what
gives an honest error bar for the same procedure at a genuinely blind bay.

Inference skill is positive at 20 of 35
stations (median 0.006), and concentrated where stations actually
disrupt: the ones with real slowdowns score 0.2 to 0.44, quiet stations score
near zero. Neighbours tell you something when something is happening and nothing
when nothing is. Reported rather than tuned.

Expected Information Gain is now a real computation — ½·log₂(1 + σ²/n²) bits from
the GP posterior — replacing the hand-weighted heuristic the dashboard shipped
with earlier. Those weights were mine; these are a measurement.

**This required changing the simulator.** Per-part service times and tags were
conditionally independent across stations, so there was genuinely nothing for a
soft sensor to infer and virtual metrology correctly failed. The brief names the
real root causes as *upstream part quality* and *environmental conditions* —
shared, which is precisely why they are hard to isolate. We added two latent
causes (incoming batch quality, an ambient OU walk) with variance-preserving
loadings, so marginal distributions and the drift scenario are unchanged while
cross-station correlation is now real (r ≈ 0.30–0.35).

## Little's Law — the twin auditing itself

WIP = throughput × flow time. An identity, not a model, so when the twin's own
reconstructed numbers stop satisfying it, the twin has drifted from the line.

Mean absolute error **9.0%** over 275
rolling windows against a 10% tolerance. Every other module
produces a prediction; this one produces a reason to distrust the predictions.

## Conformal calibration

Previously we bisected the threshold until the observed false-alarm rate hit a
target — the right instinct, but an empirical rate on one sample with no
guarantee attached, while the Round 1 deck claimed alerts were "conformally
calibrated". Split conformal makes the claim true: threshold at the
⌈(n+1)(1−α)⌉-th order statistic of in-control scores gives
P(false alarm) ≤ α, distribution-free and finite-sample.

At α = 1/1200 the threshold is 11.4508, the escape window is
21.8 parts, and zero false alarms fired on held-out
drift-free runs. `finite_sample_exact` reports **False** here:
the calibration sample is smaller than the ⌈1/α⌉ needed to certify that α exactly,
so the threshold sits at the observed maximum, which is conservative. The field is
in the output rather than hidden, because a guarantee you cannot certify is worth
less than knowing you cannot certify it.

## LSTM buffer forecaster

Every other part of the flow engine is nowcasting. This forecasts buffer fill
across all 35 stations from a 10-minute lookback, so the constraint can be
predicted rather than reported.

| Horizon | LSTM | Persistence | Linear extrapolation | Skill |
|---|---|---|---|---|
| 2 min | **0.1506** | 0.1814 | 0.1896 | +0.170 |
| 5 min | **0.1816** | 0.1928 | 0.2271 | +0.058 |
| 10 min | **0.2261** | 0.2299 | 0.3233 | +0.016 |
| 20 min | **0.2528** | 0.2808 | 0.5238 | +0.100 |

Persistence — "it will be what it is now" — is the baseline that matters, and it
is a hard one: buffer levels are strongly autocorrelated over short horizons. The
LSTM beats it at 4/4 horizons, by most at two minutes (+0.170) and
least at ten (+0.016). We committed to reporting this comparison whichever way
it came out.

## GraphSAGE on the station topology graph

Two-layer mean aggregator. The task is self-supervised on the event log: will
this station be the constraint in ten minutes, with labels taken from the
detector's own output shifted forward.

| Model | ROC AUC | MCC |
|---|---|---|
| **GraphSAGE (mean aggregator)** | **0.941** | **0.535** |
| Same network, aggregation off | 0.910 | 0.369 |
| Difference | +0.031 | +0.166 |

The ablation is the same network with the neighbour term removed — identical
features, depth, width and optimiser — so the only difference between the two
rows is whether a station may see its neighbours. We expected little gain on a
near-linear chain and were wrong: aggregation is worth +0.031 AUC and
+0.166 MCC, which is consistent with blocking and starvation propagating
locally between adjacent stations.

All three now come from the backend:

- **Blinded-station uncertainty** is the Gaussian-process posterior over
  neighbouring stations. The GP was already built; it had never been connected.
  The panel now shows the posterior width against what the uncertainty would be
  with no model at all.
- **The forecast band** is an LSTM projection of the drift statistic with a
  split-conformal residual interval at 90%. Both engines already existed. If the
  backend sends no projection, none is drawn.
- **The confidence line** is replaced by the statistic's exceedance over its
  calibrated threshold and the false-alarm budget that threshold was set to.

And the underlying cause is fixed rather than the three symptoms:
`assert_no_fabricated_figures()` scans every `.jsx` display path for numeric
literals presented as measurements, runs in `run_all.py` and in the test suite,
and carries an explicit allowlist for the business assumptions that are labelled
illustrative on screen. It is verified to catch a reintroduction.
